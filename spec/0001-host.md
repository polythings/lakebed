# 1. The host boundary

**Done** · updated 2026-10-20 · versions unreleased · milestone: [0.1](milestones/v0-1.md)

## Summary

Format crates do no I/O of their own. They call a `Host` (`lakekit-core`) that the application implements over its
object store, clock, and randomness, so the same code runs in a browser, a Cloudflare Worker, a CLI, or a server, and
tests run against memory.

## Design

- **`Host`:** `get` (the object or `None`), `get_range`, `exists`, `put`, `put_if_absent` (the commit primitive:
  `false` when an object is there), `upload` (a multipart upload: parts in order, then complete or abort), `list` (by
  prefix), `delete` (missing objects are not an error), `now_ms`, `random`, and `sleep`. Paths are absolute URIs, as
  table metadata records them.
- **Futures aren't `Send`.** Methods return `impl Future`, without a `Send` bound, so a host can wrap JavaScript
  promises (wasm-bindgen). Native hosts are free to be `Send`.
- **`MemoryHost`:** objects in memory, a clock that only moves when told (or when `sleep` is called), and a seeded
  random sequence, so tests are deterministic.
- **`Error`:** one error type for all crates, with the variant saying what a caller can do: `Invalid`, `Unsupported`,
  `Conflict` (retry on the newer version), `CommitUnknown` (the commit may have landed: delete nothing it wrote, load
  the table again), `NotFound`, `Store`, and `Corrupt`. It is `non_exhaustive`.
- **Identifiers:** `uuid_v4` and `uuid_v7` from the host's randomness and clock, for file names.

## Decisions

| ID | Decision | Status |
|---|---|---|
| D1 | Format crates do no I/O: everything goes through a `Host` trait the application implements (the idea of delta-kernel-rs's `Engine`) | Accepted |
| D2 | Host futures aren't `Send`, so JavaScript hosts work; native applications lose nothing | Accepted |
| D3 | One error type across crates, whose variants say what a caller can do | Accepted |
